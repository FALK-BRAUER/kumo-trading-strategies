# backtests — momentum_rotation

One folder per backtest SET. A set IS its data: `bars.parquet` (LFS) and any other input beside it, `manifest.json`
(the extract's provenance), `README.md` (what the set is and what its variations found), `report.html` (every
variation side by side, regenerated by any run), and `variations/<variant>/` = `run.py` (identical across the set's
variations) + `parameters.json` (EVERY parameter the run used, the strategy config included) + `results/` (the eight
result files, tracked, provenance-hashed to the inputs). `run.py` calls the one runner (`backtesting.runner_sessions`)
with the same strategy code the lane trades — nothing here re-implements a decision.

Sets here: `ledger-book-daily-2024-2026` — momentum rotation over the anonymised ledger book on Alpaca daily bars, 2024-06 →: `best` (as MOMENTUM ships) and `bctrot` (BCTROT's clock and gap rule — a variation, not a strategy).

Two tests hold every set to this: `backtesting/tests/test_layout.py` (shape, provenance hashes match the inputs) and
`backtesting/tests/test_every_variation_reproduces_its_tracked_results.py` (a rerun reproduces `metrics.json`).
Exploratory studies do not live here — a study becomes a variation when it can run from the set, or it stays in
the private research record.
